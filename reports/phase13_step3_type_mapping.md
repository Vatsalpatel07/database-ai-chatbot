## 1. Executive Summary & Mapping Principles

The schema migration between SQL Server and PostgreSQL follows standard, lossless relational type mappings tailored for PostgreSQL 18 and psycopg 3 / SQLAlchemy 2.x:

1. **String / Textual Data**:
   - Fixed or bounded Unicode strings `nvarchar(n)` map to PostgreSQL `character varying(n)` where `n` is character length (`max_length // 2` in SQL Server).
   - Unbounded Unicode text `nvarchar(max)` maps to PostgreSQL `text`.
   - Standard ASCII strings `varchar(n)` map to PostgreSQL `character varying(n)`.
2. **Unique Identifiers**:
   - SQL Server `uniqueidentifier` (16-byte GUIDs formatted like `'XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX'`) maps natively to PostgreSQL `uuid`.
3. **Boolean Flags**:
   - SQL Server `bit` (0/1 integer-like) maps natively to PostgreSQL `boolean` (`true`/`false`).
4. **Dates and Timestamps**:
   - SQL Server `datetime` and `datetime2` map to PostgreSQL `timestamp without time zone` (`timestamp`). Microsecond precision is preserved.
5. **Numeric / Integers**:
   - SQL Server `int` (4 bytes) maps to PostgreSQL `integer` (`int4`).
   - SQL Server `bigint` (8 bytes) maps to PostgreSQL `bigint` (`int8`).
6. **Binary Data**:
   - SQL Server `binary(n)` / `varbinary` maps to PostgreSQL `bytea`.
7. **Identity / Sequences**:
   - SQL Server `IDENTITY(seed, increment)` maps to PostgreSQL `GENERATED BY DEFAULT AS IDENTITY`. This ensures client inserts can provide explicit IDs during migration, and subsequent inserts continue from `setval(pg_get_serial_sequence(...), max_val)`.
8. **Integrity & Constraints Policy**:
   - **Nullability**: Preserved 1:1 across all 838 columns (0 mismatches).
   - **Primary Keys**: Exactly 5 tables define primary keys in SQL Server; exactly the same 5 tables define primary keys in PostgreSQL.
   - **Foreign Keys**: SQL Server has 0 declared foreign keys. As required, 0 foreign keys are created in PostgreSQL (no artificial constraints).
